<a id="naming-for-rekon-revision-4-companion-override"></a>

# Naming For Rekon Revision 4 Companion Override

This document is not a fourth vote and not an attempt to average a human
ruling back into model consensus. The ruling is carried by
[`proposal4.glm53m.md`](/constitution/naming/exploration/proposal4.glm53m.md),
under `human:rektide` authority. This companion accepts its four decisions
as settled direction and works through their consequences in the structures
the three syntheses built.

I use the actual model identity supplied for this run in `generated.by`. I do
not mint a persona for one artifact whose future continuity is unknown. That
is not resistance to self-naming; it is `naming-reference-pressure` and
`naming-ceremony-budget` applied to the author as well as the subject.

The main assessment is simple. The syntheses did not build architectures that
depend on location being merely an address. They made several local
classification choices as if those choices were architectural necessities.
Once location itself is admitted as the declaration of identity, the reference
family, one-name locality, promise law, native planes, and repair machinery
still work. A few normative sentences and change-table rows do not.

<a id="the-settled-override"></a>

# The Settled Override

The companion carries the same four holdings as the primary override.

1. **Location-implied naming is identity.** For a tree-resident artifact, the
   bundle path is its identity. For a section, the pinned anchor extends
   that path. The tree is the namespace, and the full name is self-locating.
2. **The rename ripple is accepted cost.** Moving a canonical file or anchor
   is a rename, not a semantically neutral locator update. The cost is paid
   deliberately with hierarchy1's migration map, inbound link inventory, human
   gate, controlled rewrites, and compatibility stubs.
3. **Actors may wear hats.** A hat is a declared concern-specific alias that
   maps to one actor. A scoped role relation can coexist with it; the relation
   does not exhaust the naming function of the hat.
4. **Cross-modal aliases are ordinary precedent.** `rekon-con-naming` shows
   that a glossary form can live inside a native work ID. It is repeatable
   practice, not an anomaly tolerated only because it arrived early. Alias
   governance is earned by pressure; it is not an entrance fee.

These holdings do not weaken one-name. They specify where the one canonical
identity comes from and which additional strings are declared routes to it.

<a id="the-okf-receipt"></a>

# The OKF Receipt

The receipt in the local OKF v0.2 checkout is exact. Section 2 says:

> **Concept ID:** The path of the concept's file within the bundle, with the
> `.md` suffix removed.

That text appears in the canonical
[`SPEC.md` lines 71 through 94](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md#L71-L94).
Section 3 then defines the bundle as a directory tree. No extra minted semantic
stem mediates between the tree and the Concept ID.

The scope of the receipt should be stated honestly. An OKF Concept is one
Markdown document, so OKF directly settles document-grain identity. It does
not define section fragments, beads records, or actor identity. Rekon's human
ruling extends the same composition one step inward: a section is the document
path plus its pinned anchor. Beads remains authoritative for work names, and
OKF section 7 remains the adopted actor-string convention. This is alignment
with OKF plus a Rekon extension, not a claim that OKF already specified every
entity kind.

The three syntheses could diverge from OKF without becoming format-invalid;
OKF permits producer extensions. The material point is conceptual. They cited
OKF as a neighboring identity and trust model, adopted its actor convention,
and then made the opposite choice for the identity of its primary entity. The
human ruling removes that unacknowledged fork.

Hierarchy1's phrase **disposition replaces location** also remains true in its
stated domain. Disposition answers whether an artifact is draft, stable,
deprecated, generated, verified, or stale. Location answers which artifact it
is. A file does not become trustworthy because it occupies a favored path, and
frontmatter does not give it a second identity because the path names it. Trust
and identity are orthogonal.

<a id="location-is-the-declared-mapping"></a>

# Location Is The Declared Mapping

The syntheses repeatedly required a declared mapping from every reference back
to one semantic owner. Location identity satisfies that test without a shadow
ledger.

- A regular concept file placed at path `P.md` declares the current document
  identity `P` within its bundle authority.
- An explicit anchor `A` inside that file declares the section identity
  `P#A`.
- Project or bundle qualification extends that local identity when a reference
  crosses an authority boundary.
- A local fragment, model-elided form, flattened cross-modal spelling, or
  glossary abbreviation is a resolution form when context or a declaration
  maps it back to `P#A`.
- A symlink declares a mapping to its target rather than silently creating a
  peer canonical body. A compatibility stub declares a retired input and its
  successor. A copied regular file, by contrast, is another artifact unless an
  explicit relation says what its continuity is.

Placement is therefore an identity act. It is public, inspectable with ordinary
filesystem tools, and collision-resistant by construction: two regular files
cannot own the same path at one time. Anchors still need a local uniqueness
check, which is one reason `naming-slug-at-mint` and mechanical verification
survive.

This changes the exact-versus-semantic layer account only where that account
overgeneralized. Session handles, commit hashes, line ranges, and routing
strings remain exact locators rather than actor names under
`naming-address-vs-identity`. A knowledge path is different: in the knowledge
plane it is both meaningful coordinate and canonical identity. Register
membership follows the promise a value performs, not its punctuation.

The tree remains a coordinate, not an ontology. Lexical ancestry improves
navigation, but it does not prove causation, dependency, authorship, or
supersession. `naming-coordinate-context` and explicit relationship words still
carry those meanings. Saying that the tree names an entity does not say that
the tree explains every relation among entities.

<a id="reference-registers-under-location-identity"></a>

# Reference Registers Under Location Identity

`naming-reference-registers` survives because it classifies reference roles,
not character sets. Its name row changes; the rest becomes simpler.

| Register | Form under the ruling | Mapping obligation |
|---|---|---|
| Canonical name | Bundle path without `.md`; for a section, that path plus its pinned anchor | Declared by regular-file placement and anchor ownership; one live owner per local authority |
| Resolution form | Contextual elision, project qualification, model elision, flattened spelling, glossary aliases such as `con`, and retired inputs | Recoverable from context, a declared rule, a symlink, or a compatibility record |
| Citation token | Dense local tokens such as the carrier's `C2` | Declared in a scoped table with canonical precedence; `naming-citation-token` is unchanged |
| Locator | Root-relative Markdown link, canonical repository URL, session handle, native object pointer | Says where to reach an object; a current path may also be its canonical name because roles can overlap in one value |
| Evidence binding | Commit-pinned path and line range, receipt, or signature | States revision and scope, and proves only the bound observation |

The important correction is narrow: paths do not belong categorically in the
"churn freely and carry no meaning" row. A session address can churn freely. A
canonical knowledge path cannot; changing it invokes `naming-rename-ripple`.
The concordance synthesis already supplied the bridge when it said register
membership depends on use rather than syntax.

The tree now supplies the canonical-name-to-owner mapping directly. Explicit
registers remain useful for citation tokens, aliases, historical names,
cross-project qualification, evidence bindings, and non-tree native entities.
Frontmatter fields such as `local_knowledge_id`, where grandfathered, can serve
as compatibility or indexing projections, but they cannot silently override
the identity declared by location.

This also preserves the constitution's one-body-many-exposures pattern. A
`SKILL.md -> README.md` symlink is a declared exposure mapping, not a second
canonical knowledge body. Location identity makes the distinction more
inspectable: the filesystem itself says whether a path owns regular content or
maps elsewhere.

<a id="the-rename-ripple-priced"></a>

# The Rename Ripple Priced

The ruling exchanges cheap minting for expensive movement. The savings are
real: no independent stem allocation, no stem-to-path registry, no resolver
needed to discover the canonical local route, and no path collision possible.
The bill is also real. For a proposed move, count at least these quantities:

| Quantity | What it measures | Work it creates |
|---|---|---|
| Moved regular files | Canonical document identities being changed | One reviewed old-path to new-path entry for each file |
| Pinned anchors in those files | Section identities changed by composition | One historical old name and successor name for every affected section |
| Controlled inbound references | Markdown links, frontmatter paths, symlinks, indexes, and ticket forward anchors in repositories under control | Inventory and rewrite each reference, or deliberately leave it on compatibility |
| Distinct durable old fragments | Old deep links known to have consumers | Preserve a fragment-aware mapping, not merely an old file that opens |
| Uncontrolled external references | Remote repositories, copied prose, offline checkouts, and human memory | Cannot be exhaustively inventoried; require an old-authority compatibility surface or accepted loud failure |

This is a cost vector, not an imaginary global transaction. Consider a
hypothetical move of one file containing eight pinned sections, with
twenty-three local inbound links, three ticket forward anchors, and two symlink
exposures. The move retires nine current full names: one document and eight
sections. It presents twenty-eight controlled reference surfaces for review.
If a symlink at the old file is supported and preserves fragment behavior, one
compatibility surface may cover all old section links. If the host does not
honor that behavior, a regular stub needs the old durable anchors explicitly;
an old file that merely opens is not enough for `old.md#specific-section`.
Unknown external citations remain unknown in either case.

Hierarchy1 already names the payment procedure:

1. Write a migration map from every old canonical path to its intended new
   path, including explicit non-actions.
2. Assemble the inbound link inventory before moving anything. Include links,
   anchors, frontmatter `resource` and source paths, symlinks, indexes, and
   ticket forward anchors.
3. Put the move through a human gate. Under location identity, layout review is
   identity review.
4. Move the owner and repair controlled references in one reviewable change.
5. Leave a compatibility stub or symlink at old paths with durable consumers,
   preserving deep fragments where those fragments were cited.
6. Verify that unresolved references fail visibly. Do not let fuzzy search
   silently bind an old name to a merely similar new entity.

A compatibility path does not undo the rename. It is a retired resolution form
whose mapping points to the one current owner. Version control records the
history; the stub keeps ordinary links useful. If no compatibility promise is
made, breakage is loud and must remain loud.

The economics discourage cosmetic tree churn. Renaming a directory multiplies
the bill across every descendant identity. Moving across projects is more
expensive again because only the old authority can preserve the old qualified
name. That pressure is not an accidental inconvenience; it makes namespace
design deliberate. `naming-rename-covenant` and
`naming-convergence-repair` already describe how to pay without pretending the
world can be updated atomically.

<a id="identity-change-operations-revised"></a>

# Identity Change Operations Revised

`naming-identity-change` remains the right taxonomy, but location identity
changes two rows that all three syntheses inherited.

| Change | Identity judgment under the ruling | Required treatment |
|---|---|---|
| Heading prose edit with pinned anchor retained | Same section identity | Edit display prose; inspect whether visible divergence is still honest |
| Non-tree locator change such as session route or external resource URL | Same named entity | Update the locator register; preserve evidence where the old locator matters |
| Anchor rename inside one file | Canonical section rename, referent continuity presumed | Retire the old fragment, map it to the successor, repair inbound links |
| File rename or move | Canonical document rename and canonical rename of every anchored section, referent continuity presumed | Migration map, inbound inventory, controlled repair, compatibility at the old path when owed |
| Directory or docroot move | Batch canonical rename of the descendant knowledge namespace | Topic-by-topic human-gated migration; old authority carries compatibility |
| Symlink or declared exposure added | No new canonical body | Record it as a resolution form with one target and explicit precedence |
| Regular copy added at another path | A second artifact exists | State derivation, replacement, or co-expression explicitly; do not infer sameness from bytes |
| Semantic split or merge | Entity set changed | Mint resulting location identities and relate predecessors and successors; never silently reuse an old name |

The old "locator move, canonical stem unchanged" row is therefore wrong for a
tree-resident knowledge owner and remains right for genuinely non-identifying
locators. The identifier `naming-location-separation` is not adopted as current
general law in this companion. Its valid actor-side observation is already
carried more precisely by `naming-address-vs-identity`; its claim about
knowledge paths is overruled rather than quietly redefined.

`naming-slug-at-mint` continues to amortize a different kind of churn. The
anchor is derived from the heading at creation and then pinned, so later display
editing need not rename the section. Moving the enclosing file still changes
the full name. Stable terminal segment and deliberate full-name movement are
compatible claims.

<a id="hats-under-promise-and-currency"></a>

# Hats Under Promise And Currency

Codex's `naming-promise-currency-split` makes the restored hat model stronger,
not weaker.

- **Promise is unilateral.** An actor self-declares its canonical actor name
  and may declare concern-specific hats that mean "this alias refers to me in
  this concern." Another actor cannot impose that identity promise.
- **Currency is bilateral.** A receiving authority decides which canonical
  actor claim and which hat mappings it will resolve in its scope. An
  unaccepted declaration remains honest provenance; acceptance makes it shared
  addressability.
- **Canonicality remains singular.** The hats map to one actor owner. They do
  not become peer actor identities merely because prose can address the actor
  through them.
- **Promotion remains available.** When a concern develops independent intent,
  continuity, and accountability, it may earn a separate actor name under
  `naming-reference-pressure`. Until then, multiplying actors would misstate
  the agency present.

The primary override demonstrates the shape with
`steward/glm-5.3-max` and the hats `proposer`, `coordinator`, and `archivist`.
The containing actor declaration is the mapping: each hat points back to the
same actor. Scope matters. A bare `coordinator` may be unambiguous inside one
effort and ambiguous across a workspace; qualification or a local roll restores
the context.

`naming-role-is-relation` also survives after losing the word "not." A role
relation records what an actor undertook, for which capability and scope, under
what history. A hat supplies a concern-specific name by which that actor can be
addressed. One action may need both records:

| Strand | Question answered | Canonical actor identity |
|---|---|---|
| Actor name | Who is making the continuity promise | Yes |
| Hat alias | Which concern-specific name reaches that actor here | No; declared mapping to the actor |
| Role relation | What responsibility the actor undertook in a scope | No; typed edge with history |
| Model identity | What generated or executed this run | No; provenance fact |
| Session or task handle | Where this execution can be resumed or inspected | No; exact locator |
| Signature or artifact binding | What evidence links output to the claim | No; evidence binding |

This extends `naming-actor-braid` by restoring the alias strand the syntheses
removed. `generated.by` should still identify the canonical actor or actual
producer, as the primary override does; hats can be declared beside it and used
where their concern makes them informative. `naming-actor-handshake` governs
acceptance without erasing self-declaration.

<a id="cross-modal-aliases-as-practice"></a>

# Cross Modal Aliases As Practice

`naming-cross-modal` returns to its proposal2 meaning: names and resolution
forms may travel among Markdown anchors, filenames, YAML keys, Mermaid nodes,
actor declarations, and beads IDs. Medium constraints may contort spelling,
and glossary aliases may abbreviate components, provided the route back to the
canonical owner remains recoverable.

`rekon-con-naming` is precise precedent. The complete string is the canonical
native ID of a work entity in beads. The `con` component is a cross-modal
resolution form for `constitution`, reused inside that work name. This does not
make the ticket and this document one entity. `naming-work-knowledge-seam` and
`naming-speech-acts` still distinguish the ticket's commitment from the
document's explanation; an explicit relation connects them.

"Ungoverned aliases" means there is no central permission gate before useful
practice. It does not mean aliases may drift without consequence. A readable
local convention, nearby declaration, frontmatter list, symlink, or glossary
can supply the mapping. Once durable citations depend on an alias, that mapping
becomes another promise to maintain.

`naming-alias-collapse` remains the guard: if context or a declaration can no
longer recover one canonical owner, the form has become ambiguous or has begun
competing as another name. Governance is then earned by actual pressure: two
conflicting expansions in one scope, repeated cross-project export, a mapping
too large to inspect locally, or compatibility history too costly to remember.
Before that point, a registry would spend ceremony on a problem not yet
present.

# The Three Syntheses After The Ruling

The three respondents reached a real convergence, but they shared sources and
a shared preference for move-stable stems. Convergence evidenced the quality of
that reading; it did not grant it authority over a human design choice or over
the OKF receipt. Their structures need revision in bounded places rather than
discard.

<a id="weaver"></a>

## Weaver

[`proposal3.glm53m.md`](/constitution/naming/exploration/proposal3.glm53m.md)
actually breaks in three normative places, not merely in tone:

- "Identity is minted, not derived" is overruled for tree-resident knowledge.
  Minting is placement plus anchor creation; no separate pinned semantic stem
  outranks that declaration.
- The reference table's claim that exact addresses, including paths, churn
  freely and carry no meaning is too broad. Runtime addresses still do; a

`naming-mint-resolve-cite` becomes even more literal: mint by placing and
anchoring, resolve by following the tree or a declared mapping, cite with a
relationship. The speech-act census, plane seams, actor grammar, repair

So the answer to the primary override's question is mixed and specific. Some

## Concordance

<a id="the-corrected-compact"></a>

# The Corrected Compact

The settled direction can be stated compactly without minting another named
law:

> Within a declared bundle or project authority, a regular knowledge artifact's
> canonical identity is its tree path with the Markdown suffix removed. A
> section extends that identity with one pinned semantic anchor. The tree is the
> namespace; project qualification composes local identities across projects.
>
> One live entity has one canonical location identity per authority. Contextual
> elisions, cross-modal abbreviations, citation tokens, symlinks, exposures, and
> historical paths may resolve to it when their mapping and precedence are
> recoverable. They do not become peer canonical owners.
>
> At creation, headings follow `naming-slug-at-mint`: derive the renderer slug,
> declare that anchor, and pin it. Later display edits may retain the anchor. A
> file or anchor move is a rename and deliberately changes the full names it
> composes.
>
> Renames are human-gated migrations. Inventory inbound references, record the
> old-to-new map, repair controlled citations, preserve compatibility where a
> durable consumer warrants it, and let unmapped failures remain loud. Never
> silently search-bind a retired name to a plausible replacement.
>
> Actors self-declare canonical names and may declare multiple scoped hats as
> aliases to that one actor. Authorities decide which claims and aliases have
> currency in their scopes. Roles remain typed relations, and a concern earns a
> separate actor only when independent agency makes that distinction true.
>
> Aliases may cross media without prior central permission. Governance arrives
> when collision, ambiguity, export, or maintenance volume earns it. Work,
> knowledge, actors, evidence, and orchestration retain native authorities and
> explicit relations rather than being collapsed by shared spelling.

<a id="costs-held-in-the-open"></a>

# Costs Held In The Open

Location identity makes several costs constitutional rather than incidental.

- Directory design becomes identity design. Aesthetic reorganizations are no
  longer harmless cleanup, and a subtree move scales with every descendant.
- Names can be verbose because they carry their neighborhood. Contextual
  elision and aliases reduce speech cost, but the fully qualified identity
  remains long when the tree is deep.
- Historical imperfections remain visible. The inherited filename
  `README-heirarchy1.glm53m.md` preserves its spelling because correcting it
  would be a rename, not because the spelling became ideal.
- Wave model suffixes participate in exact artifact location. A model-elided
  reference can be useful in a context that restores it, but exact evidence
  names the model-suffixed path.
- Compatibility artifacts consume attention. They need disposition, source and
  target checks, and fragment coverage; version history alone does not repair a
  normal Markdown link.
- External citations cannot be exhaustively known. A project can promise an
  old-path compatibility surface or honest breakage, not global atomic repair.
- Symlink and renderer behavior varies. A compatibility plan must verify the
  actual publication surface rather than assume deep fragments survive.
- Paths reveal topology. Exporting a fully qualified name also exports some
  structure of the authority that named it.
- Cross-authority moves require cooperation from the old authority. The new
  project cannot leave a stub in a namespace it does not control.

The accepted benefits are equally concrete: identity is visible without a
resolver, uniqueness comes from the tree, names locate their referents, and
plain Markdown remains sufficient. The ruling chooses those properties and
pays for moves instead of paying permanent indirection on every read.

<a id="work-left-open"></a>

# Work Left Open

The ruling closes policy questions, not every representation question. Work
still remains at the deliberately deferred `naming-tool-seam`:

- define the exact reversible projection between bundle paths, fragments, and
  flattened cross-modal forms, including punctuation and model suffixes;
- test slug-at-mint across the publication renderers actually used, including
  duplicate heading and explicit-anchor behavior;
- determine which compatibility representation preserves deep fragments on
  each host: symlink, generated stub, or explicit old-anchor map;
- derive inbound inventories and reference registers from native files without
  turning the derived view into another identity authority;
- surface broken, retired, ambiguous, colliding, unresolved, and private
  references without fuzzy silent rebinding;
- discover project authority across federation;
- decide when alias volume earns a glossary, a checked register, or stronger
  governance, using observed pressure rather than a preemptive registry;
- record hats, acceptance, scope, and retirement proportionally in actor
  presences and rolls.

None of those items reopens whether location is identity, whether moves are
allowed to ripple, whether actors may wear hats, or whether cross-modal aliases
need advance permission. They derive machinery from the ruling rather than
putting the ruling back on trial.
