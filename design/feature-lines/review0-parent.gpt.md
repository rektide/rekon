# Rekon after the manuscript — a reading from this session

## Starting here, not with a new filing scheme

The human describes Rekon growing from essentially one `AGENTS.md` into a
much wider home, with session after session contributing to it. The immediate
occasion was feature-line vocabulary, especially **prime**, and a desire for
glossary-bearing global context with the spirit of `praxis/` and perhaps
constitutional standing. The constitutional/praxis analogy was exploratory,
not a request to merge those directories.

After asking for mapping without conclusions, the human invited suggestions
and several conversational passes. I initially delegated that invitation and
preselected a structural-coherence scope. The human corrected me: use what
this session has equipped the parent to see; assess in parallel, then compare.
This is that independent reading. I have not read the new Astra assessment.
It is not a controlled model comparison: the parent has the live conversation,
the collaborator receives a brief, and their prior contexts differ.

**My leading suggestion is to work on the continuity of understanding, not
start by tidying the expansion.** Rekon's new breadth can preserve reasons,
possibilities, examples, and ways of working that a command-heavy manuscript
could not. The pressure is that accumulating an account of understanding is
not yet the same as making that understanding available to the next action.

That is an interpretation of this case, not a diagnosis of every Rekon session.
Several of the things below are straightforward assistant mistakes; more
documentation is not an automatic cure or an excuse for them.

## First suggestion: make the glossary explain relationships people act on

I agree with the impulse toward a **glossary-bearing global**. Not because
every word should be defined centrally, but because global context should let
the reader inhabit the same working world before following instructions.
Otherwise it becomes a collection of imperatives containing unfamiliar nouns.

`CONTEXT.md` is already a useful shared home. It defines a
[channel](/CONTEXT.md#channel), [revision binding](/CONTEXT.md#revision),
[home](/CONTEXT.md#home), and [intent front](/CONTEXT.md#intent-front).
The feature-line question needs connections to these terms, not an isolated
alphabetical entry declaring that prime means main-but-renamed.

For discussion, the important cluster is:

| Concept | Distinction the next reader needs |
|---|---|
| Feature / concern | What work is about, not necessarily a repository or ticket. |
| Feature line | A continuing development trajectory; the same concern can have more than one historical implementation line. |
| Tip | The end of a specified line, not necessarily the newest commit anywhere in the repository. |
| Prime | The current/active tip the human is referring to; it is not established here as Tangled terminology or an automatic greatest-timestamp query. |
| Floating reference | A name intended to follow evolving work. |
| Dated reference | A date-qualified name; whether it is a frozen snapshot or an evolving dated line must be established from the relevant practice. |
| Forge default | The branch a hosting service uses as the default entry; related to, but not identical with, the current feature line. |
| Accepted documentation channel | A selected reading route with an acceptance meaning; code recency does not confer that standing. |

These are draft distinctions, **not a new accepted glossary**. In particular,
the human's “most recent, active tip” still leaves practical choices: is prime
a role held by an undated feature bookmark, a literal `prime` bookmark, or a
reference associated with the effort? What happens if two lines remain active?
Those are useful conversational questions, not reasons to defer recording the
clear distinction from a forge default.

There is existing concrete procedure. The
[reconstruction guide](/code/task-reconstruction/README.md) (lines 73–89)
shows a floating `<feature>` bookmark **and** a dated snapshot, with the latter
not moved afterward. Its documentation predates this inquiry. Although the
exact phrase “feature line” was not found by the scoped search, that does not
make the practice absent. The earlier map omitted this load-bearing source.

An example should accompany the words: February and August bookmarklet work
can both be preserved; a current route identifies which line to continue;
the forge default can be set to expose that route; none of these operations
proves deployment or runtime completeness. The example matters because it
teaches the choice the command is supposed to carry out.

## Second suggestion: let corrections change the maintained understanding

Session contributions need somewhere to leave their **difference**, not only
their existence. “We have another review” is less useful to the next reader
than “this review found that the supposed default-branch meaning came from an
assistant, not the human or the upstream API.”

I would try a small editorial habit, using existing homes rather than inventing
a tracking system. When a substantial session hands work back, explain:

1. What understanding changed, and which prior statement it corrects or extends.
2. Which words, example, or action now mean something more precise.
3. Where the maintained reader should encounter that difference.
4. What remains a live alternative, unverified claim, or human decision.

This can be a few sentences and explained links. Not every exploratory fragment
needs a ceremony, and not every thought needs immediate integration. A coherent
stage should still be saved promptly; saving and editorial incorporation are
different acts.

Here the first map should eventually carry a conspicuous correction or route
to one, rather than only leaving its inaccuracies contradicted in later files.
The old argument should survive. So should a reader's ability not to mistake
it for the current account. This assessment records the challenge without
silently editing the earlier artifact.

## Third suggestion: treat ambient context as orientation, not only prohibitions

The live manuscript has valuable hard-won details. Adding one more command
warning for each failure would not address all the behavior here. It already
said not to guess the jj DSL, not to discard unrelated work, and that empty
working-copy commits are expected.

The context worth trying would connect purpose, terms, and a few consequential
questions: What did the human mean? What line am I on? What would make this
operation complete? What does this observation establish? Then point to the
owned practice and its example. This is an elaboration of the existing
[glossary-first workshop](/design/rekon/context-weave/north-star0.gpt6a.md),
not a claim that all of these questions should become mandatory prompts.

There is also a real delivery boundary. The
[assembler implementation](/src/agents/assemble.ts) reads explicitly declared
fragments from a manifest (lines 187–230); it does not make every newly written
GLOBAL automatically active. The [root README](/README.md#rekon-sense-map)
explicitly says the candidates have not replaced the live manuscript. The
earlier “already installed” wording blurred a documented experiment with
activation. We should inspect actual readership when trying this context,
not infer success from the existence of two GLOBAL files.

I would test usefulness through a selected situation, not an entire new platform:
can a fresh reader correctly explain the feature/snapshot/prime/default
distinctions and propose the intended operation before mutating references?
Can it recognize a clarification as such rather than manufacture a new task?
A rehearsal could answer some of that; a prose label cannot.

## Constitution and praxis: a conversation worth having, not a merge yet

The human's analogy has an attractive direction: a constitutional text need
not only legislate compliance, and praxis need not only list procedures.
They can express what forms of work we want to protect and cultivate.

I would discuss three compatible readings before choosing a layout:

- **A compact common orientation:** shared language and commitments above
  specialized practice. Constitution supplies the enduring account; praxis
  shows its implications in work. Risk: the common text absorbs every concern.
- **Two cooperating voices:** constitution asks what meanings, ownership, and
  judgments we undertake to preserve; praxis asks how to explore, act, learn,
  and revise. The glossary is a shared meeting place. Risk: easy phrases about
  their relationship substitute for actually tracing a case across them.
- **A case-led connection:** retain the present domain homes and use a few
  well-chosen stories to show where practice revised a constitutional
  expectation, or a commitment changed an action. Risk: readers still need a
  short common introduction to find those stories.

These are ways to investigate the relationship, not three incompatible
directory proposals. The existing naming ruling makes moves meaningful and
deliberate; a new metaphor is not authorization to relocate the corpus.

My present preference is to begin with the cooperating voices and a concrete
case. That preserves the lively expansion while letting us discover which
common orientation is actually missing. I would not cast praxis as subordinate
implementation of a constitution that never learns from it.

## Possible next passes, to choose through the comparison

1. **Meaning and use:** deepen the prime/feature cluster with this case and the
   existing reconstruction procedure. A small but complete experiment in shared

2. **Return from sessions:** take a handful of recent contributions and follow
   whether their important differences reached their maintained homes. Inspect
   missed learning and useful additions, not merely stale links or file counts.
3. **The common voice:** read constitution and praxis together for what Rekon
   wants to make possible, what must survive, and how experience can revise it.
   Discuss a candidate shared passage before implementing structure.
4. **Actual exposure:** compare the readable sense-map with what a fresh agent
   really receives, and try a bounded change in a deliberately selected context.
   No production AGENTS cutover follows from this document.

I would not commission all four now. The comparison with the independent
reading should change this list if it exposes a more important pressure.
The human may want a broader imaginative reading before any small repair;
that is not failure to choose a suitably narrow task.
